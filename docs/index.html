1️⃣ 原本的問題 (Original Problem)

⚠️ 困境：v1.0 第一版為無狀態單次對話（Stateless），無法理解上下文

在第一版系統中，當 LINE 使用者傳送訊息時，後端採用 client.models.generate_content 進行一次性呼叫。此模式存在以下明顯缺點：

  • 無對話歷史記憶：AI 在每一次回覆後立即遺忘上一輪對話，完全無法維持上下文連貫性。
  • 代名詞無法解析：例如使用者先詢問「台灣首都是哪裡？」，AI 回答「台北」；下一句若接著問「那裡有什麼好吃的小吃？」，AI 無法得知「那裡」指的是台北，導致回答錯誤或要求使用者重新說明。
  • 個人化體驗斷裂：當使用者做自我介紹或給定特定任務規則後，下一句即被重置，無法進行多步驟的深度問答或引導式互動。

2️⃣ 修改內容 (Modification Details)

💡 改善核心：改用 Gemini Chat API 並依 LINE User ID 建立獨立對話階段（Session）

(1) 核心 AI 模組重構 (handlers/ai_service.py)

改用 client.chats.create() 取代原本的一次性請求，並建立全域的 _chat_sessions 字典管理物件：

  • 使用者獨立隔離：以 LINE 的 event.source.user_id 為 Key，讓每位使用者擁有專屬的 Chat Session，對話記憶互不干擾。
  • 自動多層模型備援：優先調用最新 gemini-3.7-flash，若遇到連線尖峰自動平滑降級備援，確保服務穩定。
  • 對話記憶重設函式：新增 reset_chat_session(user_id)，供使用者隨時清空記憶重啟話題。
# handlers/ai_service.py 關鍵改善程式碼
_chat_sessions: dict = {}

def get_chat_session(user_id: str):
    """依據 LINE 用戶 ID 取得或建立專屬的對話 Session"""
    client = get_client()
    if user_id not in _chat_sessions:
        _chat_sessions[user_id] = client.chats.create(
            model="gemini-3.7-flash",
            config=types.GenerateContentConfig(
                system_instruction=SYSTEM_INSTRUCTION,
                max_output_tokens=1500,
                temperature=0.7,
            )
        )
    return _chat_sessions[user_id]

(2) 訊息路由更新 (handlers/message_handler.py)

  • 自 MessageEvent 提取 event.source.user_id 並傳入訊息產生函式。
  • 新增 /reset 快捷指令，使用者輸入 /reset 即可手動清空歷史紀錄。
  • 更新 /help 指令選單，明確顯示「支援多輪對話記憶」與 /reset 操作說明。
