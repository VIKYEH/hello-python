2. 原本的問題 (Original Problem)

深入分析第一版使用過程中的核心限制

⚠️ 核心痛點：單次請求無狀態（Stateless），缺乏上下文記憶

第一版採用 models.generate_content 獨立呼叫，每一則訊息回答完後立即遺忘。

  • 無法解析代名詞與關聯詞：如問「台灣首都在哪？」→「台北」；再問「那裡有什麼好吃的？」，AI 無法知道「那裡」指台北。
  • 深度引導中斷：無法進行多步驟討論（如規劃行程、除錯程式碼），對話每換一句就重新開局。
  • 使用者體驗受損：在即時通訊軟體（LINE）中，使用者習慣自然連續對話，無法記憶顯得生硬。
改善動機與問題分析 3 / 6

3. 改善內容與技術架構 (v2.0)

引入 Gemini Chat Session 與使用者獨立 Session 隔離管理

💬 多輪對話記憶機制

改用 client.chats.create() 與 chat.send_message()，保留整段對話歷史，使 AI 能精準理解前文脈絡。

👥 依 LINE User ID 獨立隔離

以 event.source.user_id 為 Key 建立每位好友專屬的 Session 字典，多名用戶同時聊天互不干擾、不混淆。

🔄 新增 /reset 快捷指令

讓使用者能主動清空記憶，隨時開啟全新話題，兼顧靈活性與控制權。

🛡️ 多模型平滑降級備援

內建 gemini-3.7-flash → 3.5-flash → 3.8-flash 備援防護，尖峰時刻自動切換，永不斷線。

架構改良細節 (handlers/ai_service.py) 4 / 6
